# 「听故事」小程序改版 · 设计 Spec

> 改版对象：`D:\WorkBuddyWorkSpace\story-miniprogram`（WorkBuddy 生成的原生微信小程序工程）
> 日期：2026-11-23 · 状态：三方向初稿阶段

## 项目是什么

一个儿童有声故事小程序，现有 7 个页面（首页 / 分类 / 搜索 / 我的 / 详情 / 播放器 / 收听历史），数据全部 mock。改版范围是**视觉与交互设计**，功能结构（页面清单、mock 数据、状态字段）保持不变。

## 受众与场景

- **操作者**：3–8 岁孩子的家长（购买/挑选/操作手机的人）；**听众**：孩子
- **最高频场景**：晚上哄睡时段（睡前故事分类、播放器自带定时功能、"助眠"标签都指向它）
- **次要场景**：白天碎片时间放给孩子听；家长群里互相推荐好故事

## 入口分析（小程序特有）

| 入口 | 判断 |
|---|---|
| 家长群转发卡片 | 高频——"这个小红帽讲得好"发进群里；**转发卡是第二首屏**，必须设计 |
| 下拉"最近使用"/桌面快捷 | 高频——熟客每晚同一时段打开，首屏要给"继续听"的捷径 |
| 搜一搜 | 低频，保留 |

## 核心信息（按优先级）

1. **今晚就能用**：打开就能继续昨晚的故事 / 找到今晚要听的那一个
2. **讲得好**：谁讲的（narrator）、多少人听、多长时长——家长决策靠这些
3. **孩子爱听**：分类按孩子状态组织（哄睡 / 涨知识 / 磨耳朵），不是按内容学科

## 情感基调

温暖、安心、睡前仪式感。可以有童话气息，但操作者是成年人——不能幼稚到家长觉得"这是给孩子的玩具"，要让家长觉得"这是帮我把今晚哄睡这件事做好"的工具。

## 输出格式与尺寸（三版统一）

- 展示板 HTML（1440 宽，React 单文件，本地 vendor），每方向 **5 屏 + 1 张转发卡片**
- 5 屏 = 首页（含"继续听"）、分类页、播放页（签名处所在）、详情页、我的页；每屏可点
- 设计稿基准 375 宽（1px = 2rpx），微信胶囊/导航栏/tabBar 按 2026-11 规格画（用 skill 的 WechatFrame 外壳）
- 转发卡片 5:4
- 页面路径沿用现有工程：pages/index/index（home）、pages/category/category、pages/search/search、pages/mine/mine、pages/detail/detail、pages/player/player、pages/history/history

## 已知约束

- 主包 ≤2MB：插画图片须压缩（JPG，最长边 ~1000px），展示稿图片 base64 内嵌
- 本地图片在原生工程里必须 `<image>` 标签，不能用 CSS background-image（交付包阶段执行）
- tabBar 图标须原生 PNG（81×81，<40KB）；设计稿阶段可自绘
- 不改变微信外观（不模仿聊天/朋友圈/支付页）；主色不用微信绿
- 胶囊旁不放可点元素；字号正文 ≥12px；点按热区 ≥44px

## 现状问题（改版要解决的）

1. **封面全是渐变色块 + 大字**——最典型的"AI 做的"特征；儿童故事尤其需要插画
2. **分类入口是数字 1–5**——毫无表达力，浪费了"按孩子状态挑"的决策入口
3. **通用电商模板套壳**：问候语 + banner + 金刚区 + 横滑 + 双列网格，没有任何"故事"的题材性；首屏对"今晚哄睡"这个最高频场景零回应（没有继续听、没有晚安仪式感）
4. **播放器是通用唱片机**——3D 旋转唱片好看但对哄睡场景没有针对性（定时关灯、音量渐弱才是家长要的）
5. eyebrow "DAILY STORIES" 英文小标签、section-sub 副标题等模板装饰

## 图片需求（三版共用素材）

统一风格：温暖手绘绘本水彩风，主体居中构图，适配三种色调方向（夜色 / 纸色 / 高饱和）。6 张故事封面 + 1 张转发卡主视觉：

1. 小红帽：森林里提篮子的红帽女孩
2. 三只小猪：盖砖房的三只小猪
3. 月亮的秘密：夜空月亮与窗边孩子
4. 少年将军霍去病：骑马的古代少年将军
5. 天空篇科普：云端的热气球
6. 消失的宝石：古堡里的宝石
7. 主视觉：一盏床头灯下的故事书与月亮（转发卡 / 空状态用）
